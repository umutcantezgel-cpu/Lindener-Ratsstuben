## Komponenten-Map

### Layout Components
- `Header` (Client) — Fixed header, scroll-aware, mobile menu with `aria-expanded`
- `Footer` (Server) — Semantic `<footer>` with `<nav>`, `<address>`, `<section>`
- `SkipNav` (Server) — Skip-to-content link targeting `#main-content`

### SEO Components
- `JsonLd` (Server) — Renders `<script type="application/ld+json">`

### Providers (Client)
- `AppProvider` — App-wide state
- `UIProvider` — UI state (modals, toasts)
- `DeviceProvider` — Device detection from middleware headers

## Semantische HTML Audit (SEQ-21)

### Landmark-Regions: ✅ COMPLETE
- `<header>` → `Header.tsx` (with `<nav aria-label="Hauptnavigation">`)
- `<main id="main-content">` → `layout.tsx`
- `<footer>` → `Footer.tsx` (with multiple `<nav aria-label>`, `<address>`)
- `<SkipNav>` → First element in `<body>`

### Heading Hierarchy: ✅ CONSISTENT
- Every page has exactly one `<h1>`
- `<h2>` → `<h3>` cascades are correct across all pages
- No heading level skips detected

### ARIA Attributes: ✅ COMPREHENSIVE
- `aria-current="page"` on active nav links
- `aria-expanded` / `aria-controls` on mobile menu toggle
- `aria-label` on all `<nav>` elements
- `aria-hidden="true"` on decorative icons
- `role="dialog"` / `aria-modal="true"` on mobile overlay

### JSON-LD: ✅ IMPLEMENTED
- Restaurant schema with opening hours, address, cuisine, payment methods

## Design-Token & Styling-Ansatz

- Tailwind with CSS Custom Properties (`--font-body`, `--font-heading`)
- Brand tokens: `primary`, `accent`, `brand-header`
- Inter (body) + Lora (headings) via `next/font/google`

## Bekannte Patterns & Konventionen

- Server Components for data/SEO, Client Components for interactivity
- `PageClient.tsx` pattern: Page renders Server wrapper, delegates interactivity to Client
- Flat JSON translation files in `locales/{locale}/common.json`
- ICU MessageFormat for parameterized translations

## Bekannte Probleme & Workarounds

- `icon.tsx` Edge Runtime warning (cosmetic, low priority)
- Translation coverage: Only `en` and `de` are populated; other locales are stubs

## Architektur-Entscheidungen

1. No third-party i18n framework — custom vanilla implementation
2. Flat JSON keys enforced by CI validation script
3. Server-first locale resolution (no client-side flicker)
4. Native `Intl` APIs for date/number/currency formatting
